# フロントエンドのタスク: 失敗した PayPal のキャプチャは、チケットや注文も解放するようになった

[English](paypal-capture-failed.md) | 日本語

**バックエンドの変更:** `docs/bugs_JP.md` #31 と #33（ブランチ `fix/paypal-unavailable-capture`）。
**種類:** 破壊的変更ではない。このタスクがなくても、リターンページの文言は正しいが、バックエンドがすでにキャンセルした
注文やチケットが、履歴ではまだ「pending」と古い表示のままになりうる。
**参照:** `docs/api-spec_JP.md` §6 の PayPal のフロー、ステップ 5。以下のファイル名は `i-dolly-frontend` のもの。

## 1. バックエンドで変わったこと

`POST /payment/paypal/capture/{pg_order_id}` は、ファンが PayPal で承認した後に、チケットの券種が売り切れた、または
商品の在庫が足りなくなった場合に `404` を返し、チケットや注文は `pending` のまま残っていた。その間に販売停止になった
商品は、そのままキャプチャされていた。

現在は 3 つのケースすべてで、バックエンドは何もキャプチャせず（お金は動かない）、チケットや注文をキャンセルし、
**`status: "failed"` で 200 を返す**。拒否されたキャプチャと同じ形。理由のフィールドはないので、「売り切れ」と
「拒否」は同じに見える。

## 2. フロントエンドのタスク

### タスク 1: キャプチャが失敗した後に履歴を更新する

`src/pages/payment/PaypalReturnPage.vue` は、`payment.status === 'success'` のときだけ注文とチケットのストアを再取得
する（`force: true`）。失敗したキャプチャも注文やチケットを変える（`cancelled` になる）ので、`failed` のときも再取得する。
そうしないと、履歴と「詳細を見る」は、ページ全体を再読み込みするまで、支払い前の `pending` のスナップショットを
表示し続ける。

### タスク 2（任意）: 文言

`paypalReturn.failedNote` は、PayPal が「この支払いを確認しませんでした — 請求はされていません」と述べている。これは
今も正しい。商品がもう購入できない可能性があることも加えるとよい。例:「PayPal がこの支払いを確認しなかったか、商品が
購入できなくなりました。請求はされていません。」両方のロケールファイル（`en.js`、`ja.js`）。

## 3. 受け入れチェックリスト

- [ ] PayPal での注文を始め、データベースで商品の在庫を注文数より少なくしてから、PayPal の承認を完了する: リターン
      ページに失敗の状態が表示され、履歴で注文がキャンセル済みと表示され、PayPal に請求は出ない。
- [ ] 注文を始めた後でマネージャーの画面から商品を無効化した場合も同様。
- [ ] 通常の PayPal の注文とチケットは、これまでどおり成功で終わる。

## 4. スコープ外

- 「売り切れ」と「拒否」を区別するための、レスポンスの理由コードは実装されていない。
