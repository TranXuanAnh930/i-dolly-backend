# フロントエンドのタスク: 商品は削除ではなく無効化される

[English](product-soft-delete.md) | 日本語

**バックエンドの変更:** `docs/bugs_JP.md` #2（ブランチ `fix/product-soft-delete`）。
**種類:** 破壊的変更ではない。既存の呼び出しは動き続けるが、「削除」は「無効化」を意味するようになった。マネージャーと
管理者の画面は、まだその状態を表示せず、元に戻す手段も提供していない。
**参照:** リクエストとレスポンスの正確な形は `docs/api-spec_JP.md` にある。このファイルには、何が変わったかと、
フロントエンドがそれに対して何をすべきかだけを書く。以下のファイル名は `i-dolly-frontend` のもの。

## 1. バックエンドで変わったこと

### 1a. 商品の削除は論理削除になった

| エンドポイント | 変更前 | 変更後 |
|---|---|---|
| `DELETE /products/delete/{id}` | 行を削除し、それとともに過去のすべての注文からその商品の明細も消えた | `is_active = false` を設定する。行とすべての注文履歴は残る |
| `PATCH /products/activate/{id}` | 存在しなかった | `is_active = true` に戻す。マネージャー／管理者用で、事務所スコープは更新と同じ。不明な ID は `404`、他の事務所の商品は `403` |

これは、グループとアイドルがすでに使っているのと同じモデル（`DELETE /groups/delete/{id}` +
`PATCH /groups/activate/{id}`）。

無効化された商品は:

- ファン向けのすべての読み取りから消える: `GET /products/store-page`、`/products/all`、`/search`、`/filter`、
  `/pagination`、他の商品ページのおすすめ、グループ詳細ページの商品一覧。
- 自身の `GET /products/{id}/detail` が `404` を返す。
- 無効化された時点で、すべてのファンのカートから取り除かれる。`POST /cart/add_cart` はその商品に `404` を返す。
- 過去の注文には、名前と価格とともに引き続き表示され、売上ページも引き続き動く。

再有効化すると、商品はストアに戻る。取り除かれたカートには**戻らない**。

### 1b. マネージャーのページは、無効化された商品をフラグ付きで一覧に出す

`GET /products/manager-products-page` と `GET /products/manager-product-form-page` は、すべての商品の行に
`is_active`（bool）を返すようになり、無効化された商品も含める。編集と画像のアップロードは、無効化された商品でも
引き続き動く。

### 1c. 新しいエラーコード 2 つ

| コード | ステータス | 発生する場面 |
|---|---|---|
| `product_unavailable` | 400 | カートにまだ無効化された商品がある状態での `POST /order/checkout`。まれ: カートを読み込んでから支払うまでの一瞬の間に商品が無効化された場合だけ |
| `category_in_use` | 400 | 無効化されたものを含め、カテゴリに商品がある間の `DELETE /categories/delete/{id}`（管理者） |

## 2. フロントエンドのタスク

### タスク 1: マネージャーの商品ページ — 状態を表示し、無効化と再有効化を追加する

`src/pages/manager/ManagerProductsPage.vue` には現在、削除の操作がない（以前の物理削除が売上履歴を消して
しまうため取り除かれた。`src/services/store/products.service.js` のコメントを参照）。その理由はなくなったので、
安全な形で操作を戻す。`ManagerGroupsPage.vue` を手本にする:

- `product.is_active` から、行のクラス `is-inactive` とステータスバッジを出す（`common.statusActive` /
  `common.statusInactive` はすでにある）。
- 有効な行には**無効化**ボタン → `DELETE /products/delete/{id}`、無効な行には**再有効化**ボタン →
  `PATCH /products/activate/{id}`（`common.deactivate` / `common.reactivate` はすでにある）。
- `ProductsService.deactivate(id)` と `ProductsService.reactivate(id)` を追加し、他のマネージャー用の呼び出しと
  同じくスタッフ用のリクエスト経路を通す。
- 無効化の確認文には、何が起きるかを書く: ストアとファンのカートから消えること、注文履歴は残ること。
- どちらの操作の後も一覧を再取得する。

### タスク 2: 管理者の商品ページ —「削除」の表記を改める

`src/pages/admin/AdminProductsPage.vue` は、「削除の確認」ダイアログの後に `ProductsService.remove(product.id)` を
呼んでいる。呼び出しは引き続き動くが、商品は一覧から消えなくなり、`is_active: false` で戻ってくる。削除に失敗した
ように見えないよう、タスク 1 と同じ変更（バッジ、無効化／再有効化、正確な確認文）を適用する。

### タスク 3: 商品の編集フォーム

編集フォームは `manager-product-form-page` から商品を読み込む。これには無効化された商品も含まれるので、編集は
引き続き動く。マネージャーが編集内容がストアに出ると期待しないように、フォーム上に無効の状態を表示する
（バッジまたは注記）。

### タスク 4: ファン向けの対応

- **商品の詳細ページ:** `404` は「この商品は販売終了になった」ことも意味するようになった。ファンが古いリンク
  （注文履歴、ブックマーク）から来た場合は、エラーのトーストではなく既存の「見つかりません」の表示を出し、
  ストアへ戻るリンクを付ける。
- **注文履歴と注文の詳細:** 注文の明細が商品ページにリンクしている場合、そのリンクは上の 404 に行き着きうる。
  リンクを残して「見つかりません」のページに任せるか、すでに持っているストアのデータにその商品がないときは
  名前をただのテキストとして表示する。
- **カート:** 商品が、次に開くまでの間にカートから消えることがある。`GET /cart/see_cart` が返す行が減るだけなので
  何も壊れないが、再取得した後にローカルにキャッシュしたカートを表示し続けないこと。
- **購入手続き:** `src/i18n/locales/en.js` と `ja.js` に `errors.product_unavailable` を追加する。文言の案:
  「カートの中に、販売を終了した商品があります。カートを確認して、もう一度お試しください。」このエラーのときは
  カートを再取得する。

### タスク 5: カテゴリの削除（管理者）— 画面がある場合

`errors.category_in_use` を追加する。文言の案:「このカテゴリにはまだ商品があります。削除する前に、商品を移動
または削除してください。」無効化された商品も数に入るので、現在の UI から「削除」はできない点に注意。実際の
手段は、商品を別のカテゴリに移すこと。

## 3. 受け入れチェックリスト

- [ ] **マネージャー:** 商品を無効化すると、すぐに一覧で無効と表示され、「再有効化」ボタンが付く。
- [ ] **マネージャー:** 無効化した商品が公開のストアページから消え、その詳細の URL は「見つかりません」になる。
- [ ] **マネージャー:** その売上ページには、過去の売上が引き続き表示される。
- [ ] **マネージャー:** 再有効化するとストアに戻る。他の事務所のマネージャーは再有効化できない。
- [ ] **管理者:** 管理者の商品ページにも同じ状態と操作が表示され、「削除」という文言が残っていない。
- [ ] **ファン:** その後無効化された商品を含む注文に、その明細が名前と価格とともに引き続き表示される。
- [ ] **ファン:** カートにある商品が無効化されると、次に読み込んだときにカートから消え、合計も更新される。
- [ ] **ファン:** 古いページから無効化された商品を「カートに追加」すると、分かりやすい「見つかりません」の
      メッセージが出る。
- [ ] **編集フォーム:** 無効化された商品を開いて保存でき、無効であることが表示される。
- [ ] 両方のロケールに新しい文言がある。

## 4. スコープ外

- 一度も注文されていない商品であっても、物理削除はない。
- 商品が無効化された時点でまだ pending の PayPal 注文は、引き続き支払える（`docs/bugs_JP.md` #33）。フロントエンド
  側の対応は不要。
- カテゴリには論理削除がない。カテゴリは、商品がなくなって初めて削除できる。
